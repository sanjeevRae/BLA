You are building a delivery operations platform (similar to DHL/FedEx) using a monolithic, cost‑optimized architecture. You will use Supabase (PostgreSQL with built‑in Realtime WebSockets, Auth, and Row Level Security) as your primary database and real‑time backbone, hosted on its free tier (500 MB database, 1 GB file storage, 50k monthly active users). For backend business logic—order creation, driver assignment, route calculation, analytics, and integration with external APIs—you will write a FastAPI application. This FastAPI backend will be deployed on Render (starting with the free tier that spins down after 15 minutes, later upgrading to a paid $7‑$19/month plan for 24/7 operation). Optional Redis (Render’s managed Redis, $32/month) will be added only when you need to scale to multiple backend instances, handling session storage, WebSocket pub/sub, rate limiting, and background job queues (BullMQ). All static frontends (admin dashboard and customer portal) will be served from **Vercel or Netlify** for free. The **admin dashboard** is built with React, Tailwind CSS, and MapTiler GL JS for live map display; the **customer tracking page** is plain HTML/JS showing order status (received → on place → went for delivery → out for delivery → delivered) and the driver’s real‑time location on a MapTiler map. **Drivers** will use a mobile app (React Native or PWA) that communicates via FastAPI REST endpoints (to fetch assignments, update status) and Supabase Realtime (to send GPS coordinates every 5 seconds and receive new assignments). All **proof‑of‑delivery photos** will be uploaded directly to **Cloudinary** (using its 25 GB free storage and 25 GB monthly bandwidth), which automatically optimizes and CDN‑delivers images. For **mapping and routing**, you will use **MapTiler** (free tier: 100,000 map loads/month, no credit card required), which provides beautiful map tiles, geocoding, and vehicle‑specific routing (bike/van/truck)—and because MapTiler builds on OpenStreetMap data, you do not need a separate OpenStreetMap integration. As a fallback for advanced routing or higher free limits, you may also integrate **OpenRouteService** (2,000 directions/day free). **Email notifications** (order confirmations, daily summaries) will be sent via **EmailJS** (200 free emails/month). **SMS notifications** (status updates to customers) will be sent via **Textlocal** (India‑focused, free credits on signup, pay‑as‑you‑go at ~₹0.30/SMS) or AakashSMS. All background jobs (daily delivery reports, GPS cleanup) will be run using **Render Cron Jobs** (included) or **GitHub Actions** (2,000 free minutes/month). You will **not** use a load balancer initially; you will start with a single Render instance. When you need to scale horizontally, you will enable Render’s built‑in load balancer and use Redis Pub/Sub to synchronize WebSocket messages across multiple instances. Your **deployment workflow** is Git‑based: push code to GitHub, and Render/Vercel automatically build and deploy. The entire MVP can run at **$0/month** using free tiers; a small production deployment (50 drivers, 500 daily orders) costs about **$44/month** (Render $19 + Supabase $25), with optional Redis adding $32/month. Finally, your source of truth is the PostgreSQL schema we defined earlier, with tables for users, customers, drivers, vehicles, warehouses, orders, order_items, packages, inventory, delivery_assignments, gps_tracking, delivery_status_history, and payments (optional). You will use MapTiler for all map display and routing, Cloudinary for images, EmailJS for emails, Textlocal for SMS, and Render + Supabase + FastAPI for the core system. No microservices, no customer mobile app initially—just an internal logistics system for warehouse, dispatch, and drivers, with a simple customer tracking web page.
